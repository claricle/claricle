== Purpose

Claricle is a Ruby library and CLI for working with image files. It
detects a file's format from its bytes and gives one object and one set
of models to work with, wrapping specialist tools behind a single API.

Format detection ships today. Inspection, conformance checking and
conversion are being built on top of it.

[NOTE]
====
Version 0.1.0 was a name reservation. Its `validate`, `convert` and
`compress` commands printed "coming soon" and did nothing; they have
been removed rather than left in place. Its metadata also advertised
image compression, which was never implemented -- compression is not in
v1's scope. Rendering, editing and WMF conversion are likewise outside
v1.
====

== Etymology & Symbolism

*Claricle* = *Clari* (clarity) + *cle* (particle)

*Combined:* "Clear particle" or "Bright essence"

The name reflects what the library is for:

* *Detection* -> know exactly what a file is
* *Validation* -> clarify every pixel
* *Conversion* -> preserve the clear essence
* *Ruby* -> gem-like, small but brilliant

== What works today

* Format detection for PNG, SVG, EMF, WMF, EPS, PS and PDF
* `inspect` for EMF -- dimensions, DPI and header metadata
* `inspect` for PNG -- dimensions, colour space, bit depth and DPI
* `inspect` for SVG -- dimensions from the root, absolute units
  converted to CSS px; a relative unit such as `%` reports no dimension
* `formats`, listing each format and what Claricle can do with it
* `Claricle::Image`, built from a path or from bytes
* A unified issue and report model, serialising to and from JSON
* An error taxonomy mapped to documented CLI exit codes

== What does not work yet

* `inspect` for WMF, EPS, PS and PDF -- EMF, PNG and SVG have handlers
  so far, so the rest raise `Claricle::UnsupportedFormat`. WMF is not
  planned: the parser it would use reports "WMF parser not yet
  implemented"
* `conform` and `convert` for every format. No handler implements
  either yet, so both raise `Claricle::UnsupportedFormat`. `claricle
  formats` reports this per format, and it reads the handlers rather
  than a list, so it cannot claim an operation that is not there
* WMF beyond detection. `detect` returns `:wmf`, but no handler
  registers it, so every operation on a WMF raises
  `UnsupportedFormat`. That is deliberate: the upstream parser this
  library would use reports "WMF parser not yet implemented"

== Command Line Interface

=== Available commands

[cols="1,3"]
|===
| Command | What it does

| `claricle inspect FILE` | Report a file's format and metadata
| `claricle formats` | List the formats Claricle handles, and what it can do with each
| `claricle version` | Print the version
|===

`claricle help` lists these, plus the commands Thor contributes itself.

The operations are added as they are implemented, so this table never
lists a command that does nothing.

=== Version

[source,sh]
----
$ claricle version
Claricle version 0.1.0
----

=== Exit codes

[cols="1,4"]
|===
| Code | Meaning

| 0 | Success
| 2 | Bad invocation -- unknown command, wrong arguments, missing file
| 3 | The format is unknown, or is recognised but unsupported for that operation
| 4 | The operation failed, or something unexpected went wrong
|===

A command may also exit with a status of its own choosing, which is
passed through unchanged; the codes above are the ones this library
assigns.

Exit code 1 is reserved for a nonconformant file, which arrives with
`conform`.

== Usage

Detect a format from a path or from bytes:

[source,ruby]
----
require "claricle"

Claricle.detect(File.binread("logo.png"))   # => :png
File.open("logo.png", "rb") { |io| Claricle.detect(io) } # => :png

image = Claricle::Image.from_path("logo.png")
image.format    # => :png
image.content   # read lazily, once
----

`Image.from_path` streams the file while detecting. `Claricle.detect`
accepts a String of bytes or an IO; an IO is read to EOF from wherever
it currently sits and is never rewound.

Bytes matching no known signature raise `Claricle::UnknownFormat`. A
format that is recognised but unhandled raises
`Claricle::UnsupportedFormat` -- two different answers to two different
questions.

Hand a delegate a real path, whichever way the image was built:

[source,ruby]
----
Claricle::Image.from_content(bytes, format: :png).with_path do |path|
  # a temporary file exists here, and only here
end
----

== Architecture

[source]
----
lib/claricle/
  detector.rb          # magic-byte and XML-root format detection
  image.rb             # the object every operation takes
  registry.rb          # frozen format -> handler map
  handlers/base.rb     # what a handler subclasses
  handlers/png.rb      # PNG metadata
  handlers/svg.rb      # SVG root metadata
  handlers/metafile.rb # EMF header metadata
  models/              # Location, Issue, Report, Inspection
  errors.rb            # Error, UnknownFormat, UnsupportedFormat, ...
  cli.rb               # Thor CLI and the exit-code Runner
----

`Detector`, `Registry`, `Handlers::Base` and `Models::Base` are private
constants. The public surface is `Claricle.detect`, `Claricle::Image`,
`Claricle::Cli` (including `Cli::Runner` and `Runner::Status`),
`Claricle::VERSION`, the `Claricle::Models` classes and the error
classes.

=== Adding a format

Not one file. A new format costs:

. a handler class under `handlers/`, declaring its formats
. a `require_relative` for it in `registry.rb` -- there is no autoloading
. an entry in `Registry::HANDLER_CLASSES`, next to that require
. a probe in `Detector` -- detection is one ordered sequence, not a
  per-handler sniffer, because the probes are heterogeneous and their
  order is load-bearing
. for an inbound conversion, an entry in the source handler's target
  list together with its feature-loss rules


== Installation

Add this line to your application's Gemfile:

[source,ruby]
----
gem 'claricle'
----

And then execute:

[source,sh]
----
$ bundle install
----

Or install it yourself as:

[source,sh]
----
$ gem install claricle
----


== Development

After checking out the repo, run `bin/setup` to install dependencies.
Then, run `rake spec` to run the tests.
You can also run `bin/console` for an interactive prompt that will allow you
to experiment.

To install this gem onto your local machine, run:

[source,sh]
----
$ bundle exec rake install
----

To release a new version, update the version number in `version.rb`, and then
run:

[source,sh]
----
$ bundle exec rake release
----

This will create a git tag for the version, push git commits and the created
tag, and push the `.gem` file to https://rubygems.org[RubyGems.org].
